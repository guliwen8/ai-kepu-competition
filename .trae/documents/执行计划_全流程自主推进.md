# 执行计划（全流程自主推进）

## 当前状态（已完成）
- 参赛端：报名/材料上传/提交、我的作品列表+详情（进度与审核建议）
- 审核：FORMAT → ANONYMITY → CONTENT 三层流水线（规则+LLM 可配置降级）
- 后台：复核台（列表/详情/人工判定/重跑）
- 评审端 MVP：评委角色、分配、五维度评分、提交锁定、导出 CSV
- 质量：`smoke/admin-smoke/judging-smoke` 自动化闭环脚本

## 总目标（一次性落地成型）
- 完整赛事闭环：发布赛事 → 报名/组队 → 提交作品 → 合规初审 → 评审打分与汇总 → 公示/导出
- 上线级保障：权限、审计、监控、备份、发布门禁

## 里程碑（按依赖顺序推进）

### M1｜评审体系增强（当前迭代）
- 分配体验：作品列表勾选 + 评委列表勾选 + 一键分配（已完成）
- 进度统计：每作品已分配/已提交数量、每评委完成率、过滤与排序
- 盲化加强：评委端隐藏附件原文件名（防身份泄露）
- 评分规则增强：权重/范围/必填校验、同分规则与导出字段完善

### M2｜赛事配置与生命周期
- 赛事状态机：报名中/提交中/评审中/公示中/结束（后端强校验）
- 赛道/组别/材料要求配置化（从硬编码转为可配置）
- 报名字段配置化与隐私确认

### M3｜排名汇总与公示
- 成绩汇总：按赛道/组别汇总、排名、同分规则
- 公示页：脱敏展示与导出
- 申诉/复核入口（可选）

### M4｜上线保障（工程化）
- 审计日志：关键操作留痕（导出、改分、分配、判定等）
- 观测与告警：错误率/慢查询/队列任务（若引入异步）
- 数据迁移规范：补齐 migrations 与回滚策略
- 发布流程：预发环境门禁 + 主分支稳定基线

## 自主推进规则（不打断用户）
- 默认按 M1 → M4 顺序推进，遇到互斥设计才要求确认
- 每完成一个里程碑自动触发：Gate-0 + Gate-1 + 对应 UI 冒烟
- 里程碑“可验收”后才进入下一个里程碑

## 验收口径（最终只需你确认这份清单）
- 参赛端：可报名、可提交、可查看进度与退回原因
- 合规审核：三层任务可追溯，退回有明确建议
- 评审端：可分配、可打分、可锁定、可导出
- 管理端：可复核、可重跑、可查看统计
- 工程化：门禁脚本全绿，CI 能阻断不合格变更
