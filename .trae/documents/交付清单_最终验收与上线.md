# 交付清单｜最终验收与上线

## 1. 交付范围

- 参赛端：报名、组队、材料上传、草稿保存、提交、我的作品查询
- 审核端：FORMAT / ANONYMITY / CONTENT 三层审核链路、人工复核、重跑
- 评审端：评委授权、批量分配、五维评分、提交锁定、导出
- 公示端：公开榜单、作品详情、公示无需登录访问
- 管理端：赛事配置、当前赛事切换、审计日志查询与导出
- 工程化：requestId、审计、metrics、Alertmanager、CI/CD、部署、回滚

## 2. 最终验收命令

- 基础设施：
  - `npm run infra:up`
- API：
  - `npm -w api run build`
  - `npm -w api run start:prod`
- 后台：
  - `npm -w admin-web run build`
- 小程序：
  - `npm run miniapp:build:h5`
  - `npm run miniapp:build:weapp`
- 冒烟：
  - `npm -w api run smoke`
  - `npm -w api run admin:smoke`
  - `npm -w api run judging:smoke`
  - `npm -w api run ranking:smoke`
  - `npm -w api run audit:smoke`

## 3. 人工验收清单

- 参赛端：
  - 未登录可查看首页赛事状态与公示页
  - 登录后可创建团队、创建草稿、上传附件、提交作品
  - 投稿截止后不可再编辑/提交
- 管理端：
  - 可创建赛事、编辑时间窗口、设置当前赛事
  - 可查看审计日志、按 action/resourceType/resourceId/requestId 检索
  - 可导出审计 CSV，且不包含实名/手机号等敏感字段
- 评审端：
  - 可授权评委、分配作品、撤销分配、重新分配
  - 评委端附件不显示原文件名
  - 可完成评分并导出结果
- 公示端：
  - `/public/leaderboard` 无需登录即可访问
  - 小程序公示页类别跟随赛事配置变化
- 工程化：
  - `/healthz` 返回 db/redis 状态
  - `/metrics` 可看到 HTTP 与 DB 指标
  - 报错信息中可带 `requestId`

## 4. 发布步骤

- 预发：
  - push 到 `main`
  - 等待 `.github/workflows/ci-main.yml` 通过
  - 若已配置 `staging` secrets，则自动上传 bundle 并执行标准部署
- 生产：
  - 创建 tag：`git tag v1.0.0 && git push origin v1.0.0`
  - 等待 `.github/workflows/release.yml` 生成 Draft Release
  - 检查 release assets：
    - `api-<tag>.tgz`
    - `admin-web-<tag>.tgz`
    - `miniapp-<tag>.tgz`
    - `deploy-<tag>.tgz`
  - Publish Draft Release
  - 等待 `.github/workflows/deploy-production.yml` 完成

## 5. 回滚步骤

- 打开 `.github/workflows/rollback.yml`
- 选择环境：`staging` 或 `production`
- 选择目标 tag
- 触发后会：
  - 下载该 tag 的 release assets
  - 上传到目标服务器的 `${DEPLOY_PATH}/${TAG}/`
  - 执行 `deploy/rollback.sh`
  - 切换 `${DEPLOY_PATH}/current` 指向历史版本
  - 可选执行 hook 与 `/healthz` 校验

## 7. 交付结论

- 当前仓库已具备“开发联调、回归验证、预发部署、生产发布、回滚、基础观测与告警”的交付基础
- 最后只需在 GitHub 仓库中补齐 environments / secrets，并在服务器放置对应 hook，即可进入真实环境上线
