# 绍兴市高校 AI 科普大赛平台（数字化赛事管理 + AI 赋能）完善计划（Plan）

## 1. 概述

本计划用于从零搭建「AI 科普大赛平台」的端到端工程与实施路线，覆盖：

- 参赛者门户（小程序为主，可扩展 Web H5）：在线报名、材料提交、进度与通知
- 智能审核引擎：三层审核流水线（格式合规 → 匿名检测 → 内容导向初审）
- 在线评审系统：盲评管理 + 五维度评分（科学准确性 / AI 技术深度 / 传播效果 / 创意 / 伦理）
- 协会管理后台（Web）：赛事配置、评委与作品管理、数据看板、公示发布、巡展管理
- AI 辅助中心：工具推荐库、选题助手、合规检查器等

技术选型（已确认）：

- 后端：Node.js + NestJS（REST）
- 数据：PostgreSQL + Redis
- 附件存储：本机/服务器磁盘（抽象存储接口，后续可迁移 S3/OSS）
- 登录：手机号验证码 + 账号密码（MVP 同时支持）
- AI 集成：第三方大模型 API（抽象 Provider，支持多家切换）

## 3. 目标与验收标准

### 3.1 总目标

建设一套“可配置、可审计、可扩展”的赛事全流程平台，实现报名—审核—盲评—公示—巡展的闭环，并用 AI 能力提升审核与运营效率。

### 3.2 MVP 验收（第一版上线必须满足）

- **参赛端**：用户注册/登录；创建团队/成员；在线报名表填写；作品（图文/视频）提交与校验；进度可视化；站内通知
- **审核端**：格式合规检查（附件类型/大小/必填）；匿名检测（正文/附件元数据/封面水印等可疑信息）；内容导向初审（规则 + AI 辅助给出风险提示与理由）
- **评审端**：评委登录；盲评分配；五维度评分 + 评语；回避/冲突声明；提交与锁定；导出结果
- **管理端**：赛事与规则配置；评委/参赛队管理；作品流转（待审/退回/通过/入评/公示）；数据看板（报名数、审核通过率、评审进度等）；公示页发布；巡展条目管理
- **系统性**：权限隔离（参赛者/评委/协会/管理员）；审计日志；异常可追溯；基础备份与恢复方案；接口文档可用

## 4. 关键约束与决策（Decision Complete）

### 4.1 赛事流程策略（针对“是否多阶段/多赛道不确定”）

- MVP 按 **单赛道单阶段** 落地：报名 → 审核 → 评审 → 公示 → 巡展
- 同时将“阶段/赛道/组别/评分项/材料要求”做成 **配置化模型**，为后续扩展留接口

### 4.2 安全与合规

- 不在日志中记录短信验证码与大模型 API Key
- 对外提供的作品展示默认脱敏（手机号、身份证号等）；仅授权角色可查看原始报名信息
- 盲评：评委端不可见参赛者真实身份字段；存储层保持“身份信息”和“盲评视图”分离
- 文件上传：白名单类型 + 大小限制 + 病毒/恶意文件预留扫描接口（MVP 可先留接口）

## 5. 总体架构

### 5.1 逻辑架构

- **客户端**
  - 小程序（参赛者门户）
  - Web 后台（协会/管理员）
  - Web 评审端（可与后台同工程不同入口/路由）
- **后端服务（NestJS）**
  - Auth & RBAC：多端统一鉴权
  - Competition：赛事/组别/规则配置
  - Submission：报名/作品/附件
  - Review Pipeline：审核流水线（异步任务）
  - Judging：盲评分配/评分/回避
  - Publication：公示/巡展
  - Notification：站内信（可扩展短信/邮件/公众号）
  - AI Center：选题/合规/摘要/风险提示
- **基础设施**
  - PostgreSQL：主数据
  - Redis：缓存、分布式锁、队列（用于审核流水线）
  - File Storage（Disk）：附件本地存储（可替换 S3）

### 5.2 工程架构（Monorepo）

建议采用 Monorepo，统一 TypeScript、共享类型与 SDK：

- `apps/api`：NestJS 后端
- `apps/admin-web`：协会管理后台（Web）
- `apps/judge-web`：评审端（可与 admin-web 合并为同 Next.js 工程的不同模块）
- `apps/miniapp`：Taro 小程序（参赛者端）
- `packages/shared`：共享类型、常量、DTO、校验规则
- `packages/sdk`：前端调用 API 的客户端封装（基于 OpenAPI 生成或手写）

## 6. 领域模型（首版）

### 6.1 核心实体

- User：用户（多端登录）
- Role / Permission：角色与权限
- Organization：单位/学校（可选）
- Team：参赛团队（含成员、队长）
- Competition：赛事
- Track/Group（配置化）：赛道/组别
- Submission：报名/作品（图文或视频）
- Attachment：附件（上传文件、封面、承诺书等）
- ReviewCase：审核实例（关联 Submission）
- ReviewTask：审核任务（格式/匿名/导向）
- Judge：评委账号（登录与权限）
- JudgeProfile：评委实名档案（姓名/单位/职称/联系方式等，默认仅组织方/管理员可见）
- Assignment：评审分配（Submission ↔ Judge）
- ScoreSheet / ScoreItem：评分表与评分项（五维度可配置）
- Score：评分记录
- Announcement：通知/公告
- Publication / Exhibition：公示与巡展
- AuditLog：审计日志

### 6.2 状态机（建议）

- SubmissionStatus：DRAFT → SUBMITTED → (NEED_FIX | UNDER_REVIEW) → (REJECTED | APPROVED) → IN_JUDGING → (PUBLICIZED | ARCHIVED)
- ReviewTaskStatus：PENDING → RUNNING → PASS/FAIL/NEED_MANUAL
- AssignmentStatus：ASSIGNED → SCORED → LOCKED

## 7. 审核流水线（智能审核引擎）

采用异步队列（Redis）驱动的三层流水线，输出结构化审核结果并支持人工复核：

1. **格式合规**
   - 必填字段、附件格式/大小、视频时长/分辨率（可选）、命名规范
2. **匿名检测**
   - 文本：姓名/单位/手机号/身份证等模式识别（规则 + 可选 NER/LLM）
   - 文件：元数据（作者/软件信息）、水印检测预留
3. **内容导向初审**
   - 规则：敏感词、违规指向、伦理风险清单
   - AI：给出“风险等级 + 触发点 + 建议操作（通过/退回修改/人工复核）”

输出：

- `review_summary`：总体结论（PASS/FAIL/NEED_MANUAL）
- `findings[]`：命中项（类型、证据、位置、置信度、建议）
- `ai_trace`：仅存储可审计的摘要信息，不保存用户隐私与提示词敏感内容

## 8. 评审模式与评分体系

### 8.1 评审模式（按赛事配置）

- 评审模式可在“赛事/阶段/赛道”维度配置：
  - 盲评：评委端不展示参赛者/单位信息
  - 非盲评：评委端可展示参赛者/单位等基础身份信息
  - 半盲评（预留）：可配置隐藏字段集合（如仅隐藏单位/姓名）
- 无论是否盲评：评委端默认不展示报名隐私字段（手机号、身份证等）
- 评委需维护实名档案（姓名、单位、职称/头衔、联系方式等），仅对组织方/管理员可见（对外展示可后续配置）
- 评委分配支持：
  - 手动分配（MVP 必做）
  - 自动分配（按领域标签/负载均衡，后续）
- 回避/冲突：评委对指定 Submission 可声明回避，触发重新分配

### 8.2 五维度评分表

- 评分项：科学准确性 / AI 技术深度 / 传播效果 / 创意 / 伦理
- 每项：分值范围、权重、是否必填、评语要求（配置化）
- 汇总：可配置加权总分、去掉最高/最低（可选）、同分排序规则（可选）

## 9. AI 辅助中心（MVP 目标）

### 9.1 工具推荐库

- 工具条目：名称、用途、标签、链接、适用场景、合规提示、推荐理由（可由 AI 辅助生成）
- 管理端可维护；参赛端可检索与收藏

### 9.2 选题助手

- 输入：目标受众、领域、传播形式、时长/篇幅
- 输出：选题候选、结构大纲、风险提示、参考资料清单

### 9.3 合规检查器

- 输入：图文稿/文案/视频文案
- 输出：敏感点、伦理风险、AI 生成内容标注建议、可替换表达

### 9.4 Provider 抽象（第三方大模型）

- 统一接口：`generate`, `moderate`, `extract`（结构化输出）
- 多 Provider 支持：配置切换 + 降级策略（超时/限流时回退到规则引擎）

## 10. 接口与契约（API 规划）

采用 REST + OpenAPI（Swagger）：

- `/auth/*`：注册、登录、短信验证码、刷新 token、退出
- `/users/*`：用户与权限
- `/competitions/*`：赛事配置、组别/评分项配置
- `/teams/*`：团队、成员
- `/submissions/*`：作品 CRUD、提交、状态查询
- `/attachments/*`：上传/下载（带鉴权）、预签名（预留）
- `/reviews/*`：审核结果查询、人工复核、重跑审核
- `/judging/*`：评委、分配、评分表、评分提交与锁定
- `/announcements/*`：公告与站内消息
- `/public/*`：公示页、巡展页（匿名化输出）
- `/ai/*`：选题/合规/摘要/工具推荐（按权限分层）
